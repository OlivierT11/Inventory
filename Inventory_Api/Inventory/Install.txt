// Database SQL via Entity Framework 
https://makolyte.com/ef-core-how-to-create-a-database-and-a-table/#Install_the_EF_Core_nuget_packages
à la racine du projet :
dotnet add package Microsoft.EntityFrameworkCore.SqlServer
dotnet add package Microsoft.EntityFrameworkCore.Design

The dotnet ef tool is used to install and update the database:
dotnet tool install --global dotnet-ef

Création initiale de la DB :
dotnet ef migrations add InitialCreate
	> crée un dossier Migrations
dotnet ef database update

Erreur : "Une erreur liée au réseau ou spécifique à l'instance s'est produite lors de l'établissement d'une connexion à SQL Server. Le serveur est introuvable ou n'est pas accessible.

// déplacer un sln 
Suppose you currently have:
MyApp/
└── Project/
    ├── Project.sln
    ├── Project.csproj
    └── Program.cs

Target layout:
MyApp/
├── Project.sln
└── Project/
    ├── Project.csproj
    └── Program.cs

From the MyApp folder, run:
mv Project/Project.sln .
dotnet sln Project.sln remove Project.csproj
dotnet sln Project.sln add Project/Project.csproj


// Docker
créer un Dockerfile et un .dockerignore à la racine du projet ASP.NET et du projet React
créer un docker-compose.yml à la racine de la solution (contient les 2 projets), et y mettre les 2 projets en tant que services
aller dans le répertoire du docker-compose.yml et exécuter (pour la prod): 
    docker compose -f docker-compose.prod.yml up -d --build
corriger les erreurs de build et relancer la commande (note, les erreurs "var crée mais jamais utilisé" sont bloquantes ici, mais pas dans npm run dev)
aller dans docker desktop > containers (il y a 2 containers) > choisir le container du projet react > cliquer sur "open in browser" pour ouvrir l'appli react dans le navigateur

Si erreur "NetworkError when attempting to fetch resource."
> dans appsettings.json du backend, autoriser l'IP du frontend: 
    "AllowedOrigins": [
      "http://localhost:5173"
    ]

Si erreur 500 : LocalDB is not supported on this platform.
LocalDB est une fonctionnalité SQL Server disponible principalement sous Windows. L'application ASP.NET Core tourne probablement dans un conteneur Linux, où MSSQLLocalDB n’existe pas.

Si erreur database:
> cf les logs du service sql server : docker compose -f docker-compose.prod.yml logs sqlserver (ils sont aussi dans docker desktop)

/ Swagger versus Postman
Swagger UI is useful when you want documentation tied directly to the API code. 
Postman is more focused on manually creating and organizing API requests.
Swagger:
    Automatically documents endpoints
    Shows the API contract
    Lets you try requests interactively
    Can support client-code generation
Postman:
    Offers advanced request collections
    Supports complex testing workflows
    Is useful for manually testing many services
A common workflow is to use Swagger for API documentation and basic testing, and Postman for more advanced testing.
